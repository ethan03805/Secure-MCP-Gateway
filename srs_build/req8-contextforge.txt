### FR-22 ContextForge integration (planned, v1.3.0)

TEXT: The owner decided on 2026-10-18 to integrate IBM ContextForge (`github.com/IBM/mcp-context-forge`, Apache-2.0) so that users get real MCP servers: (a) **catalog import**, where an operator browses the ContextForge catalog and imports entries into the Trusted MCP Server Library, and (b) a **bundled ContextForge** instance that runs as a contained, loopback-only backend through which imported hosted servers are reached. Every requirement in this section is planned for release v1.3.0 (Section 2.8). None is part of the requirement set of the current release. The ContextForge facts these requirements rest on (release v1.0.11 of 2026-09-28, the `mcp-catalog.yml` format, the configuration keys, the cosign signing of `ghcr.io/ibm/mcp-context-forge` and the 2026 security advisories) are cited as `CF:` and were read on 2026-10-18. Not planned for any release yet and recorded as future work: a Gateway-held OAuth 2.1 client for hosted entries that need OAuth (FR-22.3 classifies them `unsupported`), federation with remote ContextForge instances (outside the owner's decision), and ContextForge's REST and gRPC tool wrapping.

TEXT: Terms used below. A **local entry** is a catalog entry that names a repository and an install command for a self-hosted server. A **hosted entry** is a catalog entry whose `url` is a remote HTTPS MCP endpoint and that names no install command. A **hosted package** is a signed package built from a hosted entry; its manifest names the hosted endpoint in an `upstream` member that only the bundled ContextForge instance serves (manifest_version 2). The **bundled instance** is the one ContextForge process or container that the ContextForge Connector (E-36) runs. The **release lock** is `packaging/contextforge.lock.json` of the Gateway release.

@FR-22 | ContextForge integration
P: —
S: The Gateway release SHALL let an operator import servers listed in the IBM ContextForge catalog into the Trusted MCP Server Library under the same packaging, signature, provenance, sandbox and policy checks as any other package, and SHALL provide a bundled, contained ContextForge instance through which imported hosted servers are reached, with every tool call mediated by the Gateway.
A: E-36; E-13; E-15; F-107; F-108; F-109; X-19; X-20
V: Analysis | Review the verification results of every FR-22 child requirement and of SR-3-6, SR-3.2-2, SR-3.5-2, SR-3.6-2, SR-3.8-2, SR-4-3, SR-4.5-4, SR-4.7-3, SR-2.10-2, SR-2.13-5, SR-5.6-3 and SR-6.18-2; confirm each has passed.
SRC: OWNER (2026-10-18: integrate IBM ContextForge; catalog import into the Library; bundled ContextForge with the Gateway authoritative; opt-out possible; federation with remote ContextForge instances out of scope); ARCH §4 E-36; ARCH §18.11
R: The reference packages give four servers. The ContextForge catalog lists about 135 real servers; importing them through the Library keeps one admission path, and the bundled instance gives hosted servers a contained place to run without letting an agent reach them except through the Gateway.
TARGET: v1.3.0

TEXT: **Catalog discovery and import (F-107).**

@FR-22.1 | Catalog source
P: FR-22
S: The ContextForge Connector (E-36) SHALL read the ContextForge catalog only from the `mcp-catalog.yml` of the ContextForge release pinned in the release lock, after verifying its SHA-256 against the lock, or from an operator-supplied catalog file whose SHA-256 the operator confirms, and SHALL NOT fetch a catalog over the network while the Gateway runs.
A: E-36; F-107; X-19
V: Test | List the catalog from the pinned file, from a pinned file with one byte changed, and from an operator file with and without the confirmed digest, with outbound network access blocked; confirm the first and the confirmed operator file load, the others are refused with `CATALOG_DIGEST_MISMATCH`, and no network connection is attempted.
SRC: OWNER (users browse ContextForge's catalog); CF: `mcp-catalog.yml`, `MCPGATEWAY_CATALOG_FILE`; SEC 3.6
R: A catalog that can change under the operator after review would let a third party alter what an import proposes. ContextForge's catalog is a YAML file in its release, so it can be pinned like any artifact.
TARGET: v1.3.0

@FR-22.2 | Bounded catalog parsing
P: FR-22
S: The ContextForge Connector (E-36) SHALL parse a catalog file of at most 4 MiB and 2,000 entries as YAML without anchors, aliases, tags or merge keys, SHALL bound every string field to 4,096 characters, and SHALL refuse the whole file when any bound or rule is violated.
A: E-36; F-107; X-19
V: Test | Load catalogs that exceed each bound and catalogs using an alias expansion ("billion laughs"), a custom tag and a merge key; confirm each is refused within 1 second with the violated rule named and the Gateway's memory use rises by less than 64 MiB.
SRC: CF: `mcp-catalog.yml` (135 entries in v1.0.11); SEC 7.11
R: The catalog is untrusted input (X-19). YAML expansion attacks and oversized fields are the cheapest ways to exhaust a parser.
TARGET: v1.3.0

@FR-22.3 | Entry classification
P: FR-22
S: The ContextForge Connector (E-36) SHALL classify each catalog entry as `local` when it names a `repo` and an `install` command, `hosted` when its `url` is an `https` URL and it names no `install` command, and `unsupported` otherwise, and SHALL record the reason for each `unsupported` entry, including an `http` URL to a non-loopback host, an `auth_type` containing `OAuth2.1`, and a missing required field.
A: E-36; F-107; X-19
V: Test | Classify the pinned v1.0.11 catalog and fixture entries of each kind; confirm every entry receives exactly one class and each unsupported fixture carries its named reason.
SRC: CF: `mcp-catalog.yml` fields `url`, `auth_type`, `transport`, `repo`, `install`, `requires_api_key`
R: The two import paths differ: a local entry is code that can be pinned and inspected, a hosted entry is a remote service that cannot. OAuth 2.1 hosted entries need a Gateway-held OAuth client that v1.3.0 does not have (listed as future work in the introduction to this section).
TARGET: v1.3.0

@FR-22.9 | Hosted entry probe
P: FR-22
S: For a hosted entry, the ContextForge Connector (E-36) SHALL obtain the tool list through a quarantine probe in which the bundled instance reaches only the entry's host through an E-18 egress endpoint, holds no secret, and receives no secret other than a probe secret that the operator binds for that probe through S1 delivery.
A: E-36; E-18; F-107; F-109; I-25
V: Test | Probe a fixture hosted server that requires an API key and one that does not, with a second fixture host reachable on the network; confirm the tool list is read, the bundled instance's connections go only to the E-18 endpoint for the entry's host, the probe secret reaches the fixture as a header and appears nowhere in the bundled instance's environment, files or database.
SRC: SEC 3.5; SEC 3.7; OWNER (an imported server never runs until it passes the same checks as any other package)
R: The manifest must come from a live tool list (FR-14.3). A hosted server cannot be probed without its network, so the probe is narrowed to the one host instead (SR-3.5-2).
TARGET: v1.3.0
