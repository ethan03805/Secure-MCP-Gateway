FR-11 states: "The Gateway SHALL meet the CP-32 performance targets on recorded reference hardware with the reference dataset." Its verification is an Analysis: "Review the performance test report; confirm each FR-11 child passed on the recorded hardware."

Inputs:

- The recorded reference hardware: the GitHub-hosted `ubuntu-24.04` standard runner class (x86_64, 4 vCPU, 16 GiB, SSD), recorded in [reference-hardware.md](../reference-hardware.md) under SRS §1.6.
- The performance report: `perf.json` of the CI job `perf` of run https://github.com/ethan03805/Secure-MCP-Gateway/actions/runs/39203581561 (main, commit above, conclusion success), published as the `performance` member of the status data for that commit (`site-data/status.json`, generated 2026-10-19T05:19:21Z). Its `host` names the processor, memory, disk, runner environment and image above, and `referenceHardware` is true: the host matches `perf.ReferenceClass` (`internal/perf/measure.go`).
- The reference dataset (FR-11.1): 9,995 rules and 5 registry nodes, 256 candidate rules per decision, 100,000 journal events over 30 days, 8 concurrent callers, 1,200,000 observation records.
- The requirement report of the same run (status job), which counts each child's claiming tests.

Every child requirement of FR-11 is verified in the requirement report of this run, and each measurement of the `perf` job is a complete measurement within budget on the recorded reference hardware, which `tools/reqreport` counts as a full claim only under those two conditions ([reference-hardware.md](../reference-hardware.md#how-the-measurements-count)).

Deviations: the processor model of the reference class varies from run to run; this record covers the run above (Intel Xeon Platinum 8573C). FR-11.6 and FR-11.8 were measured with the DuckDB Observation Store of the SRS stack (§3.1), which the perf job's binaries use; the release archives are built without cgo and use the JSON Lines store, which is not measured at this volume (`docs/security-limitations.md`). A later `perf` run on main that fails a budget is a failing test and makes the child requirement failing in that run's report, independently of this record.
