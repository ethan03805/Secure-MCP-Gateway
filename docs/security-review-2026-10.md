# Security review, October 2026

Adversarial review of the Gateway at commit `067ccbc` (main, 2026-10-16), done before the v1 release. The reviewer took four positions: an attacker on the internet reaching the Remote Access listener through Tailscale Funnel or a Cloudflare quick tunnel; a malicious MCP server launched by the Gateway; a harness or agent holding a session; and another local account on the Gateway host. Each finding lists its severity, where it is, and its status. Fixed findings have a regression test in the same change. A follow-up review on 2026-10-17 covered what the first did not (the evidence journal verifier and export, listen streams on the MCP endpoint, the secret broker with the package launcher, live application of observation objects) and closed RR-07; its findings are SR-14 to SR-17.

Severity scale: **Critical** (remote compromise without credentials), **High** (compromise or data exposure from a position the threat model admits, such as a malicious server), **Medium** (denial of service from an unauthenticated position, credential guessing made easier, secret exposure that needs a second condition), **Low** (defense in depth, information exposure of little value).

No critical findings.

## Findings

| ID | Severity | Location | Finding | Status |
|---|---|---|---|---|
| SR-01 | High | `internal/pipeline/filters.go` (`compileSchema`) | A backend's tool `inputSchema` or `outputSchema` is compiled with `santhosh-tekuri/jsonschema`, whose default loader resolves `$ref` to `file://` URLs and resolves relative names against the working directory. A malicious server could make the Gateway open any local path with the Gateway account's rights: a FIFO or device to hang the call, or a local JSON file (state files, credential files) used as a schema, whose validation result then depends on its content. Confirmed with a test: a `$ref` to a temporary file changed the validation outcome. | Fixed: the compiler uses a loader that loads nothing, so only references inside the schema document and the built-in meta-schemas resolve; a schema with an external reference fails closed with a `schema-validate` finding. Tests: `TestValidateArgumentsRefusesExternalRefs`, `TestValidateArgumentsInternalRefs`. |
| SR-02 | Medium | `go.mod` | `go.mod` did not require a patched toolchain. Built with the Go 1.26.1 toolchain on the development machine, `govulncheck` reported 33 reachable standard-library advisories, among them `html/template` context-tracking bugs that affect the OAuth sign-in pages (GO-2026-4865, GO-2026-6599), an `x509` name-constraint bypass (GO-2026-4866) and an `os.Root` escape (GO-2026-4970). CI and release builds use the latest 1.26.x and were not affected; `make build` and `make release-snapshot` on an older local toolchain were. | Fixed: `toolchain go1.26.9`; with it `govulncheck ./...` reports no reachable advisories. One advisory in `golang.org/x/crypto` (GO-2026-5932, no fixed version) is in a package the Gateway does not call. |
| SR-03 | Medium | `internal/remote/limits.go` | The per-source OAuth rate limiter kept one bucket per caller address and, when 10,000 were tracked, pruned only entries idle for 10 minutes and then added the new one anyway. A caller rotating source addresses (an IPv6 /64 has 2^64) grew the table without bound and got a fresh limit per address. | Fixed: IPv6 addresses count as their /64 for limits and lockout; when 10,000 live keys are tracked, new keys share one overflow bucket. Tests: `TestRateKey`, `TestLimiterTableBounded`. |
| SR-04 | Medium | `internal/authguard/authguard.go` | Same pattern in the guard's per-source rate table (control API sign-in, console sign-in, OAuth endpoints): pruning removed only expired entries, so one minute of rotating sources could grow it without bound. | Fixed: a new source arriving while the table holds `MaxEntries` live sources uses a shared overflow key. Account failures are always recorded (each costs an Argon2id evaluation, which bounds their rate). Test: `TestSourceTableBounded`. |
| SR-05 | Medium | `internal/remote/oauth.go` (`register`) | Dynamic Client Registration is unauthenticated. Each registration with a client secret ran Argon2id (64 MiB) outside the guard's concurrency bound, and the secret was hashed and a `DCR_PENDING` event committed before the pending-queue limit was checked. With the default `concurrency_total = 16` this allowed about 1 GiB of hashing memory at once and a journal event per refused request. | Fixed: a full queue is refused first (429, no hashing, no event); hashing runs under the guard's bound (`Guard.Hash`), 503 when busy. Tests: `TestRegistrationRefusedWhenFullBeforeWork`, `TestHashBounded`. |
| SR-06 | Medium | `internal/remote/oauth.go` (`authorizePOST`, `devicePOST`) | Remote Session Approver sign-in failures locked the client ID and the caller address, not the username. An attacker could spread password guesses for one approver over every approved client and many source addresses. | Fixed: a Session Approver username is locked on the remote sign-in pages after twice `lockout_failures` failures counted over all clients and sources, recorded as `REMOTE_APPROVER_LOCKOUT` with a digest of the username. Local sign-in has its own per-username lockout and is unaffected. Test: `TestRemoteApproverLockoutAcrossClients`. |
| SR-07 | Medium | `internal/session/oauth.go`, `internal/remote/oauth.go` (token endpoint) | A second redemption of an authorization code was refused but the session created by the first redemption stayed valid. OAuth 2.1 section 4.1.3 asks that tokens issued from a code redeemed twice be revoked, since reuse means the code leaked. | Fixed on the local and remote authorization servers: redeemed codes are remembered until they would have expired; a second redemption ends that session and records `AUTH_CODE_REUSE`. Tests: `TestAuthorizationCodeReuseRevokesSession`, `TestRemoteAuthorizationCodeReuseRevokesSession`. |
| SR-08 | Medium | `internal/backend/backend.go` (`launch`) | When a server failed the MCP handshake, the start error quoted its whole retained stderr (up to 1 MiB). A server can print its environment, which holds secret values delivered by environment (S2). The error reaches the diagnostic log under the attribute `err`, which redaction does not cover, and the service manager's log. | Fixed: the error quotes at most the last 2 KiB, and every secret value delivered to that instance is replaced with `[REDACTED]` before the cut. Test: `TestStderrForErrorBoundsAndRedacts`. |
| SR-09 | Medium | `internal/consoleapi/audit.go` (`/api/v1/audit/stream`), `internal/approval/http.go` (`/api/v1/approvals/watch`) | Both event streams checked the bearer token only when opened. A stream kept delivering evidence events or approval notices after the token was signed out or expired (administrator and console sessions last 30 minutes). The number of open streams was unbounded. | Fixed: `adminapi.StillAuthenticated` re-resolves the token; the streams check it before each event and keep-alive and end when it fails. At most 32 streams of each kind are open; more get 503 with `Retry-After`. Tests: `TestStillAuthenticated`, `TestEvidenceStreamEndsAfterSignOut`, `TestEvidenceStreamLimit`, `TestWatchStreamLimitAndRevalidation`. |
| SR-10 | Medium | `internal/keys`, `internal/app/app.go` | The operator token, CA key, listener key and evidence signing keys are created with mode 0600, but their modes were never checked again. A state directory copied, restored by hand or changed with a loose umask let any local account read the operator token (administrator access) or the signing keys. | Fixed: `keys.CheckPrivate` runs before the Gateway loads its keys and refuses to start when any of those files has group or other permission bits, naming the `chmod` that fixes it. Test: `TestCheckPrivate`. |
| SR-11 | Low | `internal/metrics/metrics.go` | The loopback metrics endpoint answered any `Host`. A web page using DNS rebinding could read it from the operator's browser (server aliases, tool names, outcome counts). | Fixed: only a loopback address or `localhost` is accepted as `Host`; others get 421. Test: `TestMetricsHostCheck`. |
| SR-12 | Low | `internal/approval/notify.go` | The Linux desktop notifier passed the title and body to `notify-send` as positional arguments. The body begins with the public tool name, part of which a backend chooses; text starting with `-` could be read as an option. | Fixed: `--` precedes the title and body. The macOS notifiers already quote or pass values after option names. Test: `TestNotifySendEndsOptions`. |
| SR-13 | Low | `internal/research/export.go` (`Exporter.Open`) | Export IDs and file names allowed `.` and `..`, and a symbolic link inside an export directory was followed. The HTTP router cleans dot segments before routing, so this was not reachable through the control API. | Fixed as defense in depth: names cannot start with a dot, and files are opened with `os.OpenInRoot`. Test: `TestOpenStaysInsideExports`. |
| SR-14 | Medium | `internal/library/runtime.go` (`verifyingLauncher`), `internal/backend/backend.go` (`start`) | Found in the follow-up review (2026-10-17). The package artifact check (SR-3-2) wraps the launcher outside the Secret Broker's launcher wrapper, and the broker delivers launch-time secrets (S1 header grant, S3 files, S4 values) in `Resolve`, before the launch. When the artifact check refused the launch and suspended the revision, the broker's wrapper never ran, so the S1 grant stayed bound in the Egress Broker and the S3 files stayed in the runtime directory until the next launch of that alias or shutdown. | Fixed: when the launcher returns no process, the registry tears down the broker's deliveries for the alias (`Teardown`, idempotent), recorded as `withdrawn` with reason `LAUNCH_FAILED`; the same applies when building the environment fails. Test: `TestRefusedLaunchWithdrawsDeliveries`. |
| SR-15 | Low | `internal/edge` (harness and remote MCP endpoint) | Found in the follow-up review. A session could open any number of `subscriptions/listen` streams, each an SDK session and goroutines that live until the session ends, and the streams were counted only when the `Mcp-Method` header named the method (the SDK checks that header only for single requests at protocol 2026-07-28 and later). Writes on a stream had no deadline, so a reader that stopped reading held a blocked writer until its session ended. | Fixed: listen streams are classified by the method of the parsed body (`internal/edge/mediate.go`) and bounded to CP-20 `listen_streams_per_session` (default 2) per session, as FR-1.38 asks, and 256 in total; more get `-31005` with `LISTEN_LIMIT`. Each write and flush on a listen stream has a 10 s deadline; a write that misses it ends the stream. Tests: `TestListenStreamsBoundedPerSession`, `TestListenStreamsBoundedInTotal`, `TestListenWriterSlowReader`. |
| SR-16 | Low | `internal/audit/export.go` (`Exporter.Sync`) | Found in the follow-up review of the evidence journal. The exporter replaced the exported anchor with the journal's anchor without comparing them, and replaced the exported `evidence-genesis.pub`. A local attacker who rolled the anchor back (RR-08) had the older anchor copied over the off-machine reference at the next export. Already-exported segments are never overwritten, so a later verification of the export still failed, but the export itself reported success. | Fixed: the exported anchor only moves forward (an older segment or event count, or the same segment with another hash, is refused with an error naming a rollback), and the exported trust root is write-once. Test: `TestExporterRefusesRollbackAndTrustRootChange`. |
| SR-17 | Low | `internal/audit/audit.go` (`VerifyWith`) | `ed25519.Verify` panics on a public key of the wrong length. The command-line and backup callers check the key file, but the library function did not. Events in the trailing open segment were counted with the signed ones without saying they are unsigned. | Fixed: a trust root that is not 32 bytes is an error; `Report.OpenEvents` counts the unsigned events and `smcpctl journal verify` prints it. Tests: `TestVerifierAdversarialCases` (also covers swapped segments, reordered and removed events, a truncated last segment, an appended newline, a tampered, replaced or malformed anchor). |

## Residual risks

Not fixed in the first review; recorded so that they are tracked. The follow-up review (2026-10-17) changed the status of RR-02, RR-05 and RR-07 as noted in the table.

| ID | Severity | Location | Risk | Recommendation |
|---|---|---|---|---|
| RR-01 | Medium | `install.sh` | The installer checks the archive against the checksum file of the same release. It does not verify the Sigstore bundle that the release workflow publishes for that file, so a replaced release asset set would pass. | Verify `<project>_<version>_checksums.txt.sigstore.json` with `cosign verify-blob` and the release workflow identity when `cosign` is installed, and say when it is not. The command is in the release job summary. |
| RR-02 | Low (was Medium) | `internal/remote` | An unauthenticated caller can fill the pending registration queue (`max_pending_registrations`, default 32), so new legitimate registrations get 429 until the operator denies the pending ones. | Reduced (2026-10-17): one caller address (IPv6: one /64) may hold at most `max_pending_per_source` (default 4) pending registrations, and a pending registration is dropped after `pending_registration_lifetime` (default 24 h, was 7 days); both are in CP-49. Filling the queue now takes 8 addresses and lasts a day. Remaining: a caller with many addresses can still fill it; operators of cloud agents can pre-register clients (`remote.clients`). Tests: `TestRegistrationPerSourceQuota`, `TestPendingLifetimeAndQuota`. |
| RR-03 | Low | `internal/remote` | Lockouts are a denial-of-service lever: anyone who knows an approved client ID or a Session Approver username can keep it locked for `lockout` on the remote listener. This is the cost of the FR-16.6 lockout. | Accepted. Local sign-in stays available. |
| RR-04 | Low | `internal/remote/http.go` | The caller address comes from the tunnel's header (rightmost `X-Forwarded-For` entry by default). With a tunnel that does not set the configured header, every caller shares one address; with a header name the tunnel does not overwrite, the caller chooses it. Per-client lockout still applies. | Documented in `remote-access.md`. Set `client_address_header` to the header the tunnel sets. |
| RR-05 | Low | RFC 8628 device grant | Device-code phishing: an attacker can start a device authorization for an approved client and persuade a Session Approver to enter the code. The sign-in page shows the client, its self-declared name and the caller address. | Accepted with operator guidance (2026-10-17): `remote-access.md`, "Device codes and phishing", tells Session Approvers to approve only codes they started, what to compare on the page, and how to end a phished session and revoke the client. |
| RR-06 | Low | `internal/metrics` | The metrics endpoint has no authentication (FR-17.4 makes it loopback-only). Other local accounts can read it. | Accepted; labels are limited to FR-17.5. |
| RR-07 | Low | `internal/remote/remote.go` | The remote listener loaded its certificate when it opened and did not follow listener certificate rotation until the profile was re-enabled or the Gateway restarted. | Fixed (2026-10-17): the remote listener serves the certificate through `keys.CertReloader`, as the harness and admin listeners do. Test: `TestRemoteListenerFollowsCertificateRotation`. |
| RR-08 | Low | `internal/audit` | Known: replacing the anchor with an older signed copy together with deleting later segments is not detectable on the host alone. | Set `[evidence] export_dir` to storage off the machine (FR-7.14). |

## Areas reviewed without findings

- OAuth 2.1 (local and remote): PKCE S256 only, 43-character challenge, verifier length checked, constant-time comparison; exact redirect URI match with the RFC 8252 loopback port exception only for `http` loopback hosts; codes 256-bit, one use, bound to client, redirect URI and challenge, 10-minute lifetime; refresh-token rotation with reuse detection that ends the session; tokens stored as SHA-256 digests; client secrets and passwords as Argon2id; dynamic registrations pending until an operator approves and bound to one principal; a remote refresh of a local session is refused and ends it.
- Remote Access listener: loopback bind, TLS 1.3, `Host` must be the public name, fixed path set, header and body bounds before parsing, total and per-client concurrency, per-client call rate, `Origin` check, every event marked with the remote channel.
- Control API and console: bearer tokens only (no cookies), `Origin` and `Sec-Fetch-Site` checks, JSON content type on POST, 64 KiB body bound, `Host` allowlist, no CORS headers; role matrix applied to every route with a 403 and an `ADMIN_ROLE_REFUSED` event; console CSP without inline script or style, `frame-ancestors 'none'` and `X-Frame-Options: DENY` on every HTML response; console token in `sessionStorage`.
- Session isolation: harness approval status returns 404 for another session's approval; remote sessions are accepted only on the remote listener and local sessions only on the harness listener.
- Archives: backup restore accepts only regular files with clean relative paths, creates them with `O_EXCL`, and checks every entry against the manifest; package extraction refuses links and special files and bounds file count and size.
- Command execution: every `exec.Command` uses an argument vector; the only shell is `smcpctl upgrade --start-cmd`, an operator flag. AppleScript strings are quoted.
- SSRF: the Gateway does not fetch Client ID Metadata Documents; the Egress Broker refuses reserved addresses including NAT64 and 6to4 forms after resolution; graph queries are templated with parameters.
- TLS: 1.3 minimum on every listener; no `InsecureSkipVerify` outside the test helper.
- State permissions: state subdirectories are created 0700 and secret files 0600; the vault and passphrase files are checked.
- Concurrency: `go test -race ./...` passes.
- Evidence journal verifier (follow-up review): segment numbering gaps and a journal not starting at segment 1, swapped segment files (header segment number), reordered, removed or edited events (body hash, footer count, signature), a closed segment truncated into an open one or with bytes appended (anchor and chain hashes), a missing, malformed, tampered or older anchor, an anchor signed by another key, and key-transition records without the matching `key_rotated` event are all refused. The limits are those of the design: events in the open segment are unsigned until it closes (now reported), and RR-08.
- Observation objects (follow-up review): Audit Profiles, Observation Policies and Anomaly Response Policies published from the console now apply to the running analytics service at once (collector selection and sampling rate, band thresholds, scoring and restrict-only bands); baseline contexts and the memory budget are reported as waiting for the next start. Tests: `TestPublishedObjectsApplyWithoutRestart`, `TestSetPolicyWhileRunning`.
