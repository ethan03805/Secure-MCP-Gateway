# MCP Gateway documentation changelog

## v1.0.0 — 2026-10-18 (release candidate; not tagged yet)

First release of the Secure MCP Gateway, built to SRS V1.2 and architecture V2.3. The sections below this one record how it was specified and built; this section is the release note. The tag is made by the procedure in `docs/release-checklist.md` once the last phase-5 pull requests are merged.

### What is in the release

- `smcpd`, the Gateway daemon: an MCP endpoint for local agent harnesses (Streamable HTTP over TLS on loopback, OAuth with Session Approver sign-in), the signed Policy Store and decision point, tool-call approvals with hold mode, request and response inspection, the package library with signed packages and trust anchors, the Secret Vault and Secret Broker, the Egress Broker, the Evidence Journal (hash-chained, signed) with export, health monitoring, the management console (embedded), observation with anomaly scoring, the optional Neo4j graph mirror and the Remote Access Profile for cloud agents.
- `smcpctl`, the administrative CLI, including the new `smcpctl install` (below), `upgrade` with backup and rollback, and `uninstall` with `--purge`.
- `smcp-refserver` (the packaged example server), the harness adapters `smcp-session` and `smcp-stdio`, and `smcp-connect` for cloud agents (also on npm).
- Platforms: macOS (arm64, amd64) and Linux (amd64, arm64). The Enforced profile (every server in a rootless Podman sandbox under systemd, nftables and AppArmor) runs on Linux; macOS and Linux hosts without the prerequisites run the Standalone profile, labelled "not enforced", with health `degraded: unconfined`.
- Agents tested end to end through the Gateway: Claude Code, Codex, Hermes, OpenCode and Goose (`docs/agents-conformance.md`).

### Install

- `install.sh` downloads the archive for the host, verifies the minisign signature of the checksum file with the embedded release key (`RWTQzqxkDKxPBk0ZPk07i/mcrUVaevLmrm8zRkQLqGrs14RwtUhG30Dq`, also in `SECURITY.md`), checks the Sigstore bundle when cosign is installed, then the archive's SHA-256; it installs nothing when a check fails.
- Homebrew: `brew install ethan03805/tap/smcp`.
- `smcpctl install` sets up a Standalone installation (CP-46 directories, keys, configuration, launchd agent or systemd user unit, health check) or, as root on Linux, the Enforced profile. `docs/install.md`.

### Release label and verification

- Release label: "not enforced" unless the AT-01 to AT-21 acceptance evidence for the release commit is complete and passing (FR-19.3); there is no automated labelling step yet.
- The requirement report (`make status`, published on the project site) lists every requirement as verified, partial or unverified; `docs/verification/gap-list.md` lists what no test or record covers.

### Documentation and project site

- `docs/status/elements.json`: every element note rewritten from the current code and tests (progress relay, instance restart, FR-5.20 refusal and `-31010`, FR-1.49 collision disabling only the revision, sandbox egress and secret-file mounts, AppArmor and systemd, console cookie sessions, principals and published observation objects, the real-agent results). No implementation state changed.

### Known limitations

- `docs/security-limitations.md` (what the Gateway does not protect against) and `docs/security-review-2026-10.md` (findings of the pre-release review and residual risks).
- MCP tools only: resources, prompts, sampling, elicitation and roots are not relayed; backends are local signed packages, not remote MCP servers.
- The SBOMs are separate release assets rather than files inside each archive (FR-13.1); Homebrew installs are not yet checked by a CI job that installs from the tap (FR-13.3).

### Northbound protocol conformance (E-02, E-12, E-24)

- Message mediation in front of the MCP SDK (`internal/edge/mediate.go`): invalid UTF-8 or truncated JSON gets 400 with `-32700` (FR-1.22); a batch, a JSON-RPC response object or a scalar gets 400 with `-32600` (FR-1.4); every well-formed notification, known or not, gets 202 with an empty body and is discarded (FR-1.5); `Last-Event-ID` is ignored on 2026-07-28 requests instead of refused (FR-1.16); a request whose ID is already in flight in the session gets 400 with `-32600` (FR-1.21).
- Every response echoes the request ID (FR-1.18): 401 and 503 responses read the ID from the body, and the SDK's remaining plain-text errors (wrong Content-Type, missing Accept, unsupported legacy version header, unknown legacy method) are rewritten as JSON-RPC errors (`-32600`, or `-32601` for an unknown method).
- A request carrying a progress token is answered as an event stream from its first message (FR-1.6); event-stream responses carry `X-Accel-Buffering: no` (FR-1.7).
- Listen streams: at most `listen_streams_per_session` (CP-20) per session, further requests get `-31005` with new reason `LISTEN_LIMIT` (FR-1.38); an idle stream gets an SSE comment every 15 s (FR-1.36); a stream ended by session end or shutdown ends with an empty `resultType: "complete"` response carrying the subscription ID (FR-1.37).
- Reason code `AUDIT_UNAVAILABLE` is replaced by Appendix B's `JOURNAL_UNAVAILABLE` (SR-1.2-2). A failed commit of the outcome before release now withholds the result with `-31003` instead of `-31004` (SR-6.3-1).
- Configured Argon2id verifiers (administrator, Session Approver, Approver, console accounts, client secrets) with parameters below CP-28 or above the verification bounds are refused at load (SR-2.7-1).
- `smcpctl bootstrap`, `hash-password` and `admin redeem` refuse a password given as an argument or on standard input; every `smcpctl` secret file must be mode 0600 or stricter (SR-7.5-2).

### Linux Enforced profile hardening (E-15 to E-18, FR-13.5)

- Sandboxed servers with `network = "egress"` now start instead of being refused. The launcher attaches the instance to the Egress Broker, creates the container on slirp4netns with host loopback, installs table `inet smcp_egress` in the container's network namespace through `podman unshare nsenter ... nft` before the server process starts (TCP to the instance's own broker listeners only), reads it back, then starts the container; any failure removes the container. `pipeline.EgressNetwork` gained `GuestAddr` and `LauncherConfines`, `pipeline.EgressAttachment` gained `Allow`. `TestIntegrationEgressBroker` (real Podman) and the enforced section of `scripts/ci-integration.sh` show direct egress blocked and brokered egress to a granted local HTTP server working. `docs/sandbox.md`, "Egress".
- Hostile suite, enforced profile: HF-22 mounts its fixture directory outside `/tmp` (which the sandbox reserves) and HF-24 declares `network = "egress"`; both pass, and HF-08 passes with the secret-directory mount of #36. The CI `hostile` job sets `SMCP_HOSTILE_REQUIRE_ENFORCED=1` and fails when an Enforced row (HF-20, HF-21, HF-23, HF-24) fails or the enforced profile is unavailable.
- smcpd.service under real systemd: `scripts/ci-systemd.sh`, called from the enforced section of `scripts/ci-integration.sh`, installs `packaging/linux`, bootstraps as `smcp-core`, starts the unit, checks health, makes a tool call that runs in a rootless Podman container, stops the unit and verifies the journal. With `cgroup_manager = "cgroupfs"` smcpd now enables the cpu, memory and pids controllers in its delegated service cgroup (systemd leaves them off below `DelegateSubgroup=`), and `runtime doctor` runs `podman info` with the configured cgroup manager.
- AppArmor profile `packaging/linux/apparmor/smcpd`, installed and loaded in enforce mode by `install-enforced.sh` and applied by `smcpd.service` (`AppArmorProfile=-smcpd`); CI checks that smcpd runs as `smcpd (enforce)`.
- Servers run under the CP-46 server identity: `[runtime] run_as = "smcp-srv"` (with `shared_dir`, and optionally `sudo`) makes smcpd run every Podman command as `sudo -n -E -u smcp-srv`, so containers, `conmon` and the instances' subordinate UIDs belong to `smcp-srv`, which is no longer in group `smcp`. Executables of image-less servers are staged by digest in `shared_dir/bin`. `packaging/linux/setup-server-identity.sh` (called by `install-enforced.sh`) sets up lingering, `/var/lib/smcp/srv`, a sudoers rule limited to Podman and a drop-in for `smcpd.service`. `smcpctl runtime doctor` checks the identity (`run-as`) and runs `podman info` through the rule. `scripts/ci-systemd.sh` runs smcpd.service this way and checks the owners and UIDs of the server processes.
- AppArmor profile for server processes, `packaging/linux/apparmor/smcp-server`. Rootless Podman refuses `--security-opt apparmor=`, so the profile attaches by path to `/smcp/bin/**` (image-less servers); it denies reading process environments (S4 values), writes below `/smcp` and to `/proc` and `/sys` settings, mounts, tracing and capabilities. CI checks the label `smcp-server (enforce)` and that a read the container's permissions allow (`/proc/self/environ`) is denied (`TestIntegrationServerAppArmorProfile`, `scripts/ci-systemd.sh`). New doctor warning `apparmor-server`.
- Secret files (S2, S3) for servers in an auto user namespace or under `run_as`: the launcher creates the container, reads the instance's host UID from its `uid_map` and grants exactly that UID read access through POSIX ACL entries before the server starts; the broker copies the grant to files it writes later. The `keep-id` requirement and its launch refusal are gone. New package `internal/posixacl`. `TestIntegrationSecretFilesAutoUserNS` (real Podman) and `scripts/ci-systemd.sh` (S3 secret, `smcp-srv`, auto user namespace) cover it; the sandbox probe gained `file_sha256`.
- New guide: `docs/enforced-profile.md`.

### CI stability and southbound batch screening

- Instance restart (HF-19): a call that fails because the server process exited can surface from the SDK as a bare `io: read/write on closed pipe` instead of `connection closed`. The dispatcher now treats a closed pipe, EOF and unexpected EOF like a closed connection and replaces the instance, so the next call waits for and uses the replacement instead of failing on the dead one. `TestInstanceRestartedAfterExit` failed about 1 run in 60 for this reason (CI run 39003294193).
- FR-5.20: a server-initiated request inside a JSON-RPC batch line from a backend was passed to the SDK client, which answered `roots/list` itself. The frame filter now splits a batch line and screens each member as a single message (refuse with `-32601` except ping, route progress, convert an InputRequiredResult) and passes the remaining members one per line. The HF-26 fixture gained `legacy_all` and `legacy_batch` tools that send ping, `roots/list`, `sampling/createMessage` and `elicitation/create` one per line and in one batch; `TestServerInitiatedRequestsRefused` now verifies FR-5.20 and the hostile HF-26 row checks the batch case.
- Test ports: `internal/testport` picks loopback ports below the operating system's ephemeral range and never hands out the same port twice in a process. `gwtest`, `e2e`, the hostile harness and the `smcpctl` tests use it, so a configured listener (for example the remote listener that `TestRemoteRequiresApprovedClientToken` enables after many connections) no longer collides with an outgoing connection's source port.

### Southbound protocol and dispatch failures (E-10, E-11, E-15)

- The southbound handshake is `initialize` with protocol version 2025-11-25 (FR-5.19); the SDK used to try `server/discover` with 2026-07-28 first. `smcpctl package build` probes the same way, so manifests record the era the Gateway negotiates; the `pkgtest` fixture manifests now declare 2025-11-25.
- FR-5.40: a signed package whose manifest era differs from the negotiated version is not used; the revision is suspended with `MANIFEST_DRIFT` evidence naming both versions (`pipeline.ServerSpec.NegotiatedEra`).
- A stdout line that is not one UTF-8 JSON-RPC 2.0 message ends the instance's connection; the call fails with `-31007 BACKEND_OUTPUT_INVALID` and the instance is replaced (FR-5.13, FR-5.14). Lines used to pass to the SDK client unchecked.
- A result with an unrecognized `resultType`, or one that does not decode as a `CallToolResult`, is withheld with `-31003 RESULT_INVALID`; a missing `resultType` is `complete` (FR-5.23, SR-5.20-1).
- An instance that ends after a call to a write, external, execute or unclassified tool was dispatched records the call as indeterminate with `-31009 INSTANCE_FAILED`; read-class calls keep `-31007 DISPATCH_FAILED`. The call is never sent again (SR-7.2-1).
- Closing the response stream or connection of an in-flight `tools/call` now cancels the call (the SDK runs handlers on its own context, which did not end), and the dispatcher sends `notifications/cancelled` southbound (SR-7.12-1, FR-5.26).
- New reason codes in Appendix B and `docs/troubleshooting.md`: `RESULT_INVALID`, `BACKEND_OUTPUT_INVALID`, `INSTANCE_FAILED`.
- `pipeline.InProcessLauncher.Raw` runs scripted stdio servers in process for protocol tests.

### Console security hardening (E-24)

- Browser sessions for the console (SR-2.6-1, CP-29, `internal/adminapi/browser.go`): the login routes answer a cookie session when sent `X-SMCP-Session: cookie`. The sign-in token is revoked and never reaches the page; the cookie `__Host-smcp-session` is `Secure`, `HttpOnly` and `SameSite=Strict` with a 256-bit server-side ID, a new ID at every sign-in (a cookie sent to a login route is destroyed first), 15 minutes idle and 8 hours absolute, immediate sign-out (`POST /admin/v1/session/logout`), and cancellation of the session's requests in flight when it ends. ### Security review and hardening (phase 4)

Findings, fixes and residual risks are in `docs/security-review-2026-10.md`.

- Tool schemas from backends no longer resolve `$ref` outside the schema document; the default loader read local files (`file://` and relative names), so a malicious server could make the Gateway open any local path (SR-01).
- `go.mod` requires `toolchain go1.26.9`; `govulncheck` reports no reachable advisories (SR-02).

- Server start errors quote at most 2 KiB of the server's stderr, with delivered secret values redacted (SR-08).
- `/api/v1/audit/stream` and `/api/v1/approvals/watch` end when the token that opened them is signed out or expires (`adminapi.StillAuthenticated`) and allow at most 32 open streams each (SR-09).

- The metrics endpoint answers only loopback `Host` values (SR-11); `notify-send` gets `--` before the notification text (SR-12); research export files are opened with `os.OpenInRoot` and names cannot start with a dot (SR-13).

### Protocol hardening after the hostile suite (phase 4)

- Progress relay (FR-1.39, FR-1.40, SR-5.9-1): a `tools/call` with a `progressToken` sends the backend a Gateway-issued token and relays the backend's `notifications/progress` with the northbound token, strictly increasing values, at most 10 per second per request (CP-21) and none after the response. Each message passes the response filters first (blocked: dropped; transformed: relayed as transformed) and carries provenance with the filters applied and any tags. The frame filter routes progress in line order, so notifications written before the response are relayed before it; a bounded queue keeps a slow harness from stalling a shared instance. Approval keep-alives share the call's progress sequence.
- Instance restart (Appendix L HF-17, HF-19): a call that reaches the upstream timeout (`-31009 UPSTREAM_TIMEOUT`) or finds the instance gone replaces the instance; later calls wait for the new one. A relaunch that fails or presents a different revision suspends the server.
- `InputRequiredResult` from a backend ends the call with `-31010 INPUT_REQUIRED_UNSUPPORTED` and a `failed` event (FR-5.24); the MRTR Relay Profile is not implemented.
- Server-initiated requests other than `ping` (`roots/list`, `sampling/createMessage`, `elicitation/create`) are answered with `-32601` by the Gateway and never reach the SDK client (FR-5.20); the Gateway declares no client capabilities southbound (SR-5.6-2), where the SDK used to declare `roots`.
- Public-name collisions (FR-1.49) and the other per-revision presentation errors no longer stop the Gateway: the revision is not enabled, `Registry.Disabled` keeps the reason naming both tools, and a `not_enabled` event (`SERVER_NOT_ENABLED`) is recorded.
- Enforced profile: the Secret Broker's S2/S3 directory is mounted read-only at `/smcp/secrets` and the file-path variables are rewritten, so a sandboxed server can read its secret files (the cause of HF-08 failing in the Enforced run: the fixture could not read the file, so there was nothing to block). Such a server needs `userns = "keep-id"`; with `"auto"` the launch is refused with that reason.
- FR-1.10 is verified: unknown methods answer HTTP 404 with `-32601` in the 2026-07-28 era (the SDK already did this; the note saying otherwise was stale), and HTTP 200 in the legacy era.
